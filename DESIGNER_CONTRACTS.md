## Implementation Notes for Fashion Marketplace

## Implementation Notes for Fashion Marketplace

### **Admin Dashboard Integration**

All three contracts are **downloadable as PDF/HTML/JSON** from the admin documents section:
- **Location**: Admin → Documents → Designer Contracts
- **Access**: `/admin/documents`
- **Download Formats**: TXT, JSON, HTML (easily convertible to PDF via browser print)

### **How Admin Uses Contracts**

1. **Select Contract Type**: Admin chooses which contract to send based on strategy
   - **Design Ownership Purchase**: For bulk library acquisition
   - **Premium Creator Partnership**: For long-term exclusive partnerships
   - **Work-For-Hire**: For specific trend-based commissions

2. **Download & Customize**: Admin downloads the contract in preferred format (TXT/HTML/JSON)
   - Customize terms (amounts, durations, rates)
   - Add specific designer details
   - Add project descriptions (for Work-For-Hire)

3. **Send to Designer**: Email contract with signature request
   - Use DocuSign, HelloSign, or Google Docs for digital signatures
   - Include designer instructions and FAQs
   - Set deadline for acceptance

4. **Track Agreements**: All signed contracts stored in `DesignerContract` database model
   - Admin can view which designers have which contracts
   - Track signing dates, contract status, terms
   - Monitor contract expiration/renewal dates

### **Designer Contract Database Model**

New `DesignerContract` model tracks:
- `contractType`: OWNERSHIP_PURCHASE | PREMIUM_PARTNERSHIP | WORK_FOR_HIRE
- `status`: PENDING_REVIEW | OFFERED | SIGNED | ACTIVE | ARCHIVED | CANCELLED
- `designerId`: Links to User (designer)
- `signedAt`: Timestamp of signature
- `offeredBy`: Admin email who sent contract
- `terms`: Specific amounts, rates, deadlines based on contract type

### **Workflow for Each Contract Type**

**OWNERSHIP_PURCHASE:**
1. Admin identifies designs to acquire
2. Admin customizes contract with: Purchase Price, Design IDs, Timeline
3. Admin sends contract to designer
4. Designer signs → DesignerContract.status = SIGNED
5. Payment processed → Designs transferred to platform ownership

**PREMIUM_PARTNERSHIP (3 Designs/Month - 12 Month):**
1. Admin identifies high-potential designer
2. Admin customizes: Monthly Retainer or 60% Revenue Share
3. Designer signs → status = ACTIVE
4. System tracks monthly design submissions (auto-validate 3+ designs/month)
5. Status changes to ARCHIVED after 12 months or early termination

**WORK_FOR_HIRE:**
1. Admin creates design brief/requirements
2. Admin customizes: Commission Amount, Delivery Deadline, Revision Rounds
3. Designer signs NDA clause + accepts terms
4. Designer submits design by deadline
5. Admin approves → DesignerContract.status = COMPLETED
6. Payment released → Designer retains no rights

### **How Designers Choose/Respond**

**Option 1: Self-Service Portal** (Future Enhancement)
- Designers log in → View offered contracts
- Choose contract type that fits their work style

**Option 2: Email + External Signature** (Current - MVP)

### **Key Differentiators**
| Aspect | Contract 1 | Contract 2 | Contract 3 |
|--------|-----------|-----------|-----------|
| **Ownership** | Platform owns 100% | Designer owns, Platform licenses | Platform owns 100% |
| **Payment** | One-time | Monthly retainer + commission | One-time |
| **Exclusivity** | Permanent | 90 days then non-exclusive | 24 months |
| **Designer Benefit** | Immediate cash, portfolio rights | Recurring income + badge/features | Immediate cash + portfolio credit |
| **Best For** | Bulk library building | Long-term partnerships | Trend/seasonal designs |
| **Complexity** | Low | Medium | Medium-High |
| **Admin Effort** | Minimal (bulk deals) | Ongoing (track submissions) | Moderate (brief → review) |
